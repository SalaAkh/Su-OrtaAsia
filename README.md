# SuSave

Работающее приложение на русском языке для оценки водосбережения и окупаемости повторного использования серой воды. Валюта — тенге; расчётный месяц — **30 дней**. Для квартиры, дома, гостиницы, спортклуба и других небольших объектов.

## Установка и запуск

Нужен Node.js **20.19+ или 22.12+** и npm. Проверено на Node.js 24.22.1. Из корня репозитория:

```bash
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (по умолчанию порт 5173).

```bash
npm test             # автоматические тесты расчётов, валидации и хранения
npm run typecheck    # строгая проверка TypeScript
npm run build        # production-сборка в dist/
npm run preview      # просмотр сборки, по умолчанию порт 4173
```

SuSave — статическое приложение: расчёты и сохранение полностью выполняются в браузере. При работе нет обращений к внешним API, CDN, платным сервисам или базе данных. Vite нужен для разработки и просмотра сборки; `dist/` можно разместить на любом статическом хостинге. Приложение не требует Python-бэкенд. После загрузки страницы расчёты и экспорт работают без сети; установка PWA и гарантированное повторное открытие страницы офлайн в эту версию не входят.

### Существующее приложение Su-OrtaAsia

Сохранены `backend/`, `database/`, `frontend/app.html`, прежние CSS и JS. Предыдущая главная страница перенесена без изменения содержимого в `frontend/twin.html`. Новый `frontend/index.html` открывает SuSave. Для разработки использована существующая структура статического frontend с TypeScript и Vite; React не добавлен.

Старое приложение доступно через Vite в разработке по `/twin.html` и `/app.html`. Старый Python-сервер продолжает обслуживать `/app.html` и прежний API, но не компилирует TypeScript SuSave. Production-сборка `dist/` предназначена только для SuSave.

## Возможности

- Четыре раздела: объект и расход, обычные меры, повторное использование, сравнение и окупаемость.
- Несколько независимых объектов: создание, переключение, переименование, удаление, автосохранение.
- Семь взаимно исключающих категорий потребления. Исходная сумма постоянно видна в закреплённой строке.
- Тарифы и их источник задаются вручную. Город не влияет на тарифы. Начальные объёмы, тарифы, эффекты и цены нулевые.
- Кнопка **«Загрузить условный пример»** создаёт отдельный объект с явно вымышленными данными, сохраняя существующие объекты.
- Обычные меры: пользовательский эффект в м³ или процентах, разовые и ежемесячные расходы, изменение порядка применения.
- Серые воды: выбор душа/ванны и умывальников, сбор, выход обработки, мощность, обслуживание, полный набор капитальных и эксплуатационных затрат.
- Четыре сценария, числовые карточки, таблица, график покупной воды и накопленный денежный результат за 60 месяцев.
- Экспорт всех объектов в JSON, проверяемый импорт, CSV текущего сравнения и печатный отчёт со всеми исходными данными, мерами, статьями затрат, сценариями и допущениями.
- Адаптивная светлая тема, десятичная запятая, доступные подписи полей и сообщения об ошибках.

## Расчётная модель

Чистая функция `calculate(project)` в `frontend/susave/engine.ts` — единый источник результатов для карточек, таблицы, графиков, CSV и печати. Входы и выходы типизированы. Исходный объект не изменяется; промежуточные вычисления не округляются, округление используется при отображении.

### Обычные меры

Исходный объём `V₀` — сумма семи категорий. Для каждой меры с текущим остатком категории `v`:

- абсолютная мера: `s = min(v, указанное сокращение)`;
- процентная мера: `s = v × процент / 100`;
- новый остаток: `v − s`.

Меры применяются последовательно, сверху вниз. Два сокращения по 50% оставляют 25% исходного расхода, а не ноль. Расход категории не становится отрицательным. Если ожидаемый абсолютный эффект больше остатка, фактический эффект ограничивается остатком и показывается в карточке. Указанные затраты меры при этом сохраняются.

### Повторное использование

Только душ/ванна и выбранные умывальники могут быть источником; кухня, стирка и туалетные стоки исключены. Единственное назначение очищенной воды — смыв туалетов.

```text
G = сумма подключённых категорий после обычных мер × доля сбора
D = оставшийся расход на смыв
η = выход очищенной воды / 100
C = производительность по готовой очищенной воде
R = min(G × η, D, C)
V = расход после обычных мер − R + свежая вода для обслуживания
```

Для сценария только повторного использования обычные меры не применяются. Для комбинированного сценария источник и спрос пересчитываются после мер. Экономия независимых сценариев не суммируется. Вода и расходы на обслуживание учитываются и при нулевом источнике — уменьшите их вручную, если система не используется.

### Финансы

```text
ΔV = V₀ − V
S = ΔV × тариф воды + ΔV × тариф водоотведения × коэффициент
N = S + допустимая экономия нагрева − дополнительные эксплуатационные расходы
Окупаемость = полные вложения / N, если N > 0
Результат месяца m = −полные вложения + m × N, m = 0…60
```

Коэффициент водоотведения — **финансовое допущение о начислениях** от 0 до 1. При 1 каждый сэкономленный м³ покупной воды уменьшает оплачиваемое водоотведение на м³; при 0 платёж за водоотведение не меняется. Постоянные платежи не входят в экономию. Исходная оценка переменных платежей равна `V₀ × (тариф воды + тариф стоков)`; последующая оценка вычитает `S` и отдельную экономию нагрева и добавляет эксплуатацию.

Нагрев задаётся отдельной оценкой **для конкретной меры**, уменьшающей горячую воду в душе, умывальниках, кухне или стирке. Его значение по умолчанию — 0. Он учитывается только при фактическом положительном сокращении категории. Оценка должна относиться к эффекту этой меры после предыдущих, без повторного учёта других статей. Если включён флажок «Нагрев уже включён в оценку платежей», отдельная прибавка отключается. В сценарии только повторного использования нагрев всегда равен 0.

При `N ≤ 0` выводится «При этих условиях не окупается»; при `N < 0` показываются дополнительные месячные расходы. Отрицательная экономия воды и денег не обрезается. При нулевом исходном расходе процент сокращения не определён; вместо деления на ноль выводится пояснение. При положительной экономии и нулевых вложениях срок равен нулю.

## Сохранение и перенос

Используется ключ `susave.workspace.v1` в `localStorage`. Формат JSON:

```json
{ "version": 1, "activeId": "идентификатор", "projects": ["полные объекты Project"] }
```

Полную типизированную структуру смотрите в `frontend/susave/model.ts`; корректный файл проще получить кнопкой экспорта. Проверяются вложенные поля, типы, диапазоны, даты, уникальность идентификаторов, активный объект и версия. Импорт **заменяет все объекты** после явного подтверждения; повреждённый файл ничего не изменяет. Максимум 50 объектов, 100 мер на объект, 2 МБ на импортируемый файл.

Числа конечные и неотрицательные, не более 1 000 000 000; минимальное ненулевое входное значение — 0,000001. Для процентов максимум 100, для коэффициента — 1. NaN, Infinity и экспоненциальная запись в полях не принимаются. При ошибке ввода сохраняются последние корректные данные, показывается предупреждение, переход к другому разделу и экспорт блокируются до исправления.

Хранилище привязано к браузеру и адресу страницы (включая порт). Для переноса используйте JSON. В приватном режиме или при очистке данных браузера локальные объекты могут исчезнуть. Ошибки доступа и переполнение показываются без падения приложения. Повреждённая сохранённая запись автоматически не перезаписывается: новые изменения остаются в памяти до явного разрешения перезаписи либо экспорта.

CSV использует UTF-8 с BOM, разделитель `;` и десятичную запятую. Текстовые поля защищены от интерпретации как формул электронных таблиц. Полный отчёт можно распечатать или сохранить в PDF средствами браузера.

## Проверки

```bash
npm test
npm run typecheck
npm run build
```

Тесты включают все шесть числовых примеров из задания, последовательные проценты, порядок мер, нулевой расход, лимиты источника/спроса/мощности, дополнительные расходы системы, отрицательную экономию, двойной учёт нагрева, состав затрат, невалидные входы, JSON/CSV и отказ localStorage.

В Chromium проверен полный путь: заполнение → меры → повторное использование → сравнение → JSON/CSV → импорт → перезагрузка; также создание, переименование и удаление объектов, печатный PDF, работа после отключения сети, сообщения ошибок и все четыре раздела при ширине 390 и 320 пикселей. Снимки и PDF сохраняются в игнорируемую папку `.test-artifacts/`.

Для повторения браузерной проверки в окружении с Python Playwright и Chromium:

```bash
# В первом терминале, после npm run build:
npm run preview -- --port 4173
# Во втором:
python3 tests/browser_smoke.py
```

В облачном окружении Playwright и `/usr/bin/chromium` уже установлены. На другой машине для дополнительной браузерной проверки установите Python-пакет `playwright` и Chromium; путь к браузеру можно задать переменной `CHROMIUM_PATH`, адрес приложения — `SUSAVE_URL`. Эти инструменты не нужны для работы SuSave или модульных тестов npm.

## Ограничения

Это предварительный месячный баланс, а не инженерный проект. Он не проверяет совпадение потоков по времени, объём накопителя, качество обработки, питьевую безопасность или техническую допустимость монтажа. Приложение не управляет оборудованием. Кухонные и туалетные стоки не используются. Тарифы, потребление и эффекты задаёт пользователь; нормативы и реальные тарифы не подставляются.

Финансовый прогноз предполагает неизменные тарифы, одинаковую работу каждый месяц, отсутствие дисконтирования и стоимости финансирования. Сезонность, инфляция, деградация оборудования и переменные режимы отдельно не моделируются.

## Доступ с телефона

Для открытия только с телефона нужна опубликованная HTTPS-ссылка. Подготовлен
workflow `.github/workflows/susave-pages.yml`: он запускается вручную, выполняет
тесты и сборку и размещает только `dist/` в GitHub Pages. Само наличие файла
ничего не публикует. После отправки кода в GitHub нужно выбрать в настройках
репозитория **Pages → Source → GitHub Actions**, затем запустить workflow
**Publish SuSave to GitHub Pages**. Фактическая ссылка появится в результате
успешного задания `deploy`. Доступность Pages зависит от видимости репозитория
и тарифа аккаунта GitHub. Данные объектов остаются в браузере посетителя.

Если компьютер и телефон подключены к одной Wi-Fi сети, запустите `npm run dev`
на компьютере и откройте на телефоне сетевой адрес, напечатанный Vite. Оба устройства
должны видеть друг друга в сети; адрес localhost на телефоне указывает на сам телефон.
Создание объектов поддерживается и через обычный HTTP в локальной сети.
